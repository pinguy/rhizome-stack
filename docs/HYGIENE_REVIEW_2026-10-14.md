# Hygiene review — 14 October 2026

Reviewed the supplied 0.1.0-alpha.9 archive and prepared the
0.1.0-alpha.11 candidate. This review uses that uploaded source, not an older
archive or an assumed repository revision. OpenClaw 2026.7.1-2, Open WebUI
0.11.0, model pins and the WAN generation/decoder graphs remain unchanged.

## Corrections

- **GPU hand-over:** an absent, null or malformed Ollama `models` list could
  be interpreted as an empty GPU. The bridge now validates every runner before
  sending unload requests and validates the subsequent empty-list check.
- **WAN playback:** suffix ranges such as `bytes=-4` previously returned the
  beginning of the file. Suffix, open and bounded ranges now return the correct
  bytes; unsatisfiable ranges report the file size with HTTP 416.
- **WAN requests:** JSON arrays, null and scalar values now return HTTP 400
  without reaching generation. Incomplete JSON bodies are rejected explicitly.
- **WAN batches:** seed zero previously switched to an unrelated seed on later
  takes. Fixed seeds now increment correctly, random batches randomise each
  take, and a batch that would overflow is rejected before queue insertion.
  Queue preparation also leaves the caller's payload unchanged.
- **Configuration:** the installer now decodes quoted environment values and
  JSON-escapes substituted strings. Recreating a missing OpenClaw config no
  longer changes quoted tokens or breaks on quotes/backslashes in values.
- **Documentation:** corrected the stale Ollama installation limitation,
  documented retained WAN output paths and batch seed boundaries, and linked
  this review from the README.

## Security follow-up

The subsequent review identified an unauthenticated adapter, an inaccurate
Python requirement, explicitly disabled Jupyter authentication and gaps in the
privacy audit. The alpha.11 changes address those findings:

- Adapter model/chat routes require a separate per-installation bearer secret.
  Host, Origin, fetch metadata and POST media type checks run before dispatch.
  Missing secrets fail closed; the local health endpoint remains available.
- The creative desks now authenticate their server-side adapter calls and apply
  same-origin browser/loopback Host checks so their prompt helpers cannot serve
  as a cross-site alternative route into the agent.
- The installer consumes both supported Python bounds, selects 3.11 or 3.12,
  and rejects unsupported existing managed environments before installation.
- Jupyter requires a dedicated token at process startup and in its server
  configuration. Both Open WebUI code paths receive matching token settings
  when Jupyter is explicitly selected. Container limits and mounts are retained.
- Privacy patterns now cover Brave, Hugging Face, AWS, Google, Slack and
  fine-grained GitHub tokens, numbered handles and contextual Telegram IDs.
  The audit's embedded personal identifier has been removed from current source.
  Earlier Git commits retain it; no repository history was rewritten.

Existing Open WebUI database settings can override environment defaults. Follow
[the migration instructions](SECURITY_UPGRADE.md) for saved connection keys,
Jupyter settings, image rebuilds and service restarts.

## Evidence and scope

New regression cases reproduced the configuration, Ollama-state and WAN
failures before their fixes. Added a dedicated WAN HTTP/batch suite using
synthetic media over a loopback server. Existing attachment-failure recovery
coverage now exercises music, images and video, including WAN take identity.

Validation:

- All **14 bundled suites passed**, comprising **152 unittest cases**, with
  no skips, plus static, creative graph and manifest checks.
- The declared `tests/requirements.txt` dependencies were installed in an
  isolated environment. Real FAISS storage tests used deterministic vectors;
  they do not establish embedding quality.
- Release export passed the privacy audit, allow-list and SHA-256/size checks
  for all 203 distributed files. Two independent ZIP builds matched
  byte-for-byte, as did the two tar.zst builds.
- An isolated JupyterLab 4.5.3 server using the new configuration rejected
  missing/incorrect credentials and rebinding Host headers, accepted an
  authenticated kernel create/delete cycle, and refused startup without its
  token. The token was absent from captured logs. This was a host-process test;
  Podman/container deployment and Open WebUI end-to-end execution were not run.
- `git diff --check` passed. The release manifest was regenerated by the
  exporter; private state and the local review Git history are excluded.

This was a source review and isolated regression run. No live provider chat,
GPU generation, Open WebUI browser session, runtime dependency installation,
or clean native Linux/WSL2 installation was performed. The acceptance gaps in
`KNOWN_LIMITATIONS.md` still apply. The original uploaded ZIP is retained as
the local baseline; normal first-change installation backups remain available.
